# Фінальний огляд стабільності (ТЗ §52)

Огляд проведено після завершення фаз 2–9 окремо від написання коду. Для
кожного пункту: як перевірено, що знайдено, що виправлено. Знахідки
попередніх фаз (виправлені одразу) перелічено в `IMPLEMENTATION_PLAN.md`.

| Пункт §52 | Як перевірено | Результат |
|---|---|---|

## Знайдено під час фінального огляду

1. **Зависання процесу Engine на виході, якщо GUI зник.** Черга подій
   `multiprocessing.Queue` під час завершення процесу дописує буфер у pipe;
   якщо читача (GUI) вже немає, а pipe заповнений, процес не завершиться
   ніколи. Те саме для черги журналу. Виправлено `cancel_join_thread()` для
   обох черг. Тест `test_engine_exits_even_if_nobody_reads_events`
   відтворює проблему: без виправлення процес не завершується за 30 с, з
   виправленням — за ~1 с.
2. Налаштування, передані з GUI в Engine, містили кортеж там, де перевірка
   очікувала список, — поле мовчки скидалося до значення за замовчуванням із
   попередженням у журналі. Виправлено, додано тест повного проходження
   `Settings → dict → Settings` без попереджень.
3. Зібраний EXE (PyInstaller 6) кладе файли в `_internal\` — пошук
   вбудованого FFmpeg цю папку не враховував. Виправлено; перевірено
   пробною збіркою і `--selftest`.
4. Атомарний запис не додавав префікс довгих шляхів Windows — додано.

## Знайдено першим прогоном на справжній Windows (CI `windows-latest`)

Результат першого прогону: 458 тестів пройшли, 4 — ні; самоперевірка
зібраного EXE — 11/11; тести Job Objects (вбивство дочірнього й онука при
закритті job, загибель Engine разом із GUI) — пройшли.

5. **Пошкоджена база стану не відновлювалася на Windows**: невдале
   з'єднання з SQLite лишалося відкритим, і Windows не дозволяла перейменувати
   файл у карантин. Виправлено (з'єднання закривається при будь-якій помилці
   налаштування; перейменування з обмеженими повторами).
6. **Віконна збірка без консолі**: `sys.stdout`/`sys.stderr` = `None`; будь-
   яке повідомлення Python або бібліотеки губилося. Тепер вони
   перенаправляються у `logs\console-<pid>.log`; аварія під час старту Engine
   чи GUI записується в `crash.log` і показується користувачу; Engine пише
   «engine started» у журнал. Крок GUI-перевірки в CI виводить ці файли.
7. Три тести мали помилки, специфічні для Windows (читання JSON без явного
   UTF-8, вплив змінної `VIDEOGEN_FFMPEG_DIR` у CI) — виправлено.

## Відомі обмеження

* Код Windows Job Objects, маніфест і EXE перевіряються лише в CI на
  `windows-latest` (поточне середовище розробки — Linux).
* На Linux/macOS дочірні FFmpeg не вбиваються автоматично, якщо процес
  Engine убито ззовні (на Windows це гарантує Job Object).
* MODE B: реальні адаптери ElevenLabs та OpenAI ще не підключено (лише
  інтерфейси, кеш і тестові провайдери).
