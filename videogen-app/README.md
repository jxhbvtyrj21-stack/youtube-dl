# VideoGen

Програма для Windows 10/11, яка автоматично створює відео із зображень і
аудіо: з плавним рухом камери (Ken Burns), м'якими переходами між кадрами та
розмитим фоном для зображень, що не збігаються з форматом кадру.

Головний пріоритет програми — стабільність: вона не зависає, не рендерить
безкінечно, не губить готові відео після збою і не видає пошкоджений файл
за успішний.

---

## 1. Запуск

1. Розпакуйте архів `VideoGen-<версія>-win64.zip` у будь-яку папку
   (наприклад, `C:\Програми\VideoGen`).
2. Запустіть `VideoGen.exe`.

Встановлювати Python чи FFmpeg не потрібно — усе вже всередині.

> Порада: додайте тимчасову робочу папку до винятків Windows Defender
> (див. TROUBLESHOOTING.md, розділ «Повільна робота»). Це помітно
> пришвидшує обробку великих пакетів.

## 2. Підготовка матеріалів

**Одна папка = одне відео.** Вхідна папка може містити:

* **кілька підпапок** — кожна стане окремим відео з назвою підпапки:

  ```
  Матеріали\
    Епізод 01\   audio.mp3, 001.jpg, 002.png, 003.webp …
    Епізод 02\   voice.wav, image_1.jpg, image_2.jpg …
  ```

* **або безпосередньо файли** — тоді буде одне відео з назвою папки.

У кожній папці (режим A):

* **рівно один аудіофайл**: MP3, WAV, M4A, AAC, FLAC, OGG, OPUS;
* **зображення**: JPG/JPEG, PNG, WEBP, BMP, TIFF.

Зображення йдуть у порядку імен з урахуванням чисел (`img2` раніше за
`img10`). Час рівномірно ділиться між зображеннями так, що відео рівно
відповідає тривалості аудіо.

**Режим B** (сценарій → озвучка + зображення): у папці мають бути
`script.txt` (сцени, розділені порожнім рядком) і `prompts.txt` (один промпт
на рядок, стільки ж, скільки сцен). Для режиму B потрібні налаштовані
сервіси ElevenLabs (озвучка) та OpenAI (зображення); поки їх не підключено,
програма показує «Провайдер не налаштований».

## 3. Створення відео

1. Оберіть **режим** (A або B) і **формат**: горизонтальний 16:9 або
   вертикальний 9:16.
2. **Вхідна папка** — папка з матеріалами.
3. **Папка результатів** — куди зберігати готові відео (не та сама, що вхідна).
4. **Тимчасова робоча папка** — необов'язково; за замовчуванням
   `%LOCALAPPDATA%\VideoGen\workspace`. Краще обрати папку на швидкому диску
   з достатнім вільним місцем.
5. Натисніть **START**.

Під час роботи видно: поточний етап (кадр, fps, швидкість), загальний
прогрес, прогрес поточного відео, лічильники та орієнтовний час до
завершення. Вікно залишається чутливим навіть тоді, коли щось зависло.

## 4. Керування

| Кнопка | Що робить |
|---|---|
| **PAUSE** | дочекається завершення поточного короткого фрагмента і призупинить обробку (FFmpeg ніколи не «заморожується» посередині) |
| **RESUME** | продовжує з того самого місця |
| **STOP** | зупиняє весь пакет: поточне відео скасовується, тимчасові файли видаляються |
| **CANCEL CURRENT JOB** | скасовує лише поточне відео, далі обробляються наступні |
| **OPEN OUTPUT** | відкриває папку результатів |
| **OPEN LOG** | відкриває журнал програми |

## 5. Результати

* Готові відео: у **папці результатів**, `<назва папки>.mp4`
  (H.264 + AAC, 30 кадр/с, 1920×1080 або 1080×1920).
* Наявний файл ніколи не перезаписується — нове відео отримає ім'я
  `Назва (2).mp4`.
* **` [PARTIAL]` у назві** означає, що відео створено не з повного набору
  матеріалів: частину зображень пропущено або відновлено з пошкоджених
  файлів. Які саме — видно в журналі та в архіві завдання.
* Архів завдання: `папка результатів\_archive\<назва>.zip` — `manifest.json`,
  журнал і оригінальні вхідні файли (для перевірки або повторного
  створення). Тимчасові файли рендерингу в архів не потрапляють.

## 6. Журнали та діагностика

`%LOCALAPPDATA%\VideoGen\`:

| Файл / папка | Вміст |
|---|---|
| `logs\application.log` | загальний журнал (з ротацією: до 5 файлів по 10 МБ) |
| `logs\errors.log` | лише попередження та помилки |
| `diagnostics\<завдання>\` | для невдалих і неповних завдань: `manifest.json`, детальний `job.log`, знімки стану процесів у момент зависання |
| `settings.json` | налаштування (останні вибрані папки тощо) |

## 7. Якщо сталася помилка

* Повідомлення у вікні пояснює причину простими словами, наприклад:
  «Не вдалося використати зображення №17. Файл: image_017.png. Причина:
  файл пошкоджений.»
* Одна проблема не зупиняє пакет: інші відео продовжують створюватися.
* Якщо програму було закрито аварійно (збій, вимкнення живлення), при
  наступному запуску вона запропонує для незавершених відео:
  **Продовжити** (з місця зупинки), **Почати заново** або **Ігнорувати**.
  Уже готові відео при цьому не змінюються.
* Детальні поради — у **TROUBLESHOOTING.md**.

## 8. Для розробників

* `ARCHITECTURE.md` — архітектура, машини станів, режими відмов.
* `BUILD.md` — збірка EXE.
* `TESTING.md` — тести, відповідність сценаріям ТЗ, стрес-тести.
* `IMPLEMENTATION_PLAN.md`, `OPEN_QUESTIONS.md` — план і рішення.
